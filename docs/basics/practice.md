# 把基础串成一个练习

用你写过的健康计算器，复盘输入、方法拆分、类型和输出这条完整流程。


## 先看主流程

<SourceCode id="practice" />

这份 `Practice.java` 的价值是练习程序结构。这里关注 Java 的输入、计算和输出组织，不把估算结果作为健康判断依据。

```text
创建 Scanner
  → 读取姓名、选项、年龄、身高、体重
  → 调用计算方法
  → 格式化打印结果
  → 关闭 Scanner
```

main 像一个目录，把每一步安排清楚。具体怎样读取、怎样计算，则交给各个方法。

## 一个 Scanner，多处使用

你在 main 中只创建了一次 Scanner，然后传给 `getName(sc)`、`getAge(sc)` 等方法。这让资源的创建和关闭位置集中，也避免多个输入对象争用标准输入。

## 两层输入校验

以身高输入为例：

1. `hasNextDouble()` 判断格式能不能转成 double。
2. `height > 0` 判断数值范围是否满足当前练习要求。

格式错误时用 `next()` 消耗内容，再进入下一轮。范围错误时数值已经被 nextDouble 取走，不需要再多读一次。

## 计算方法返回结果

`getBMI(...)` 和 `getBMR(...)` 返回 double；main 再决定按什么文字、单位与小数位数显示。相比让每个计算方法直接打印，返回值更容易被其他代码复用。

想看具体实现，可在上方切换到“完整源码”。

## 阅读时留意命名与单位

参数中身高的单位是厘米，计算中有厘米到米的换算。理解程序时，除了看类型，还要看数值代表的含义和单位。

原始源码、笔记摘录和整理后的解释可能存在时间差。本页以同步到的源文件为准，例如现在姓名输入已经使用 nextLine，而较早笔记里还讨论过 next 的局限。

## 本章回顾

能解释下面五个问题，第一章就已经串起来了：

- 为什么入口写 static，而某些方法要先创建对象再调用？
- 为什么 double 转 int 不是四舍五入？
- 为什么 hasNextInt 判断失败后要取走错误输入？
- 为什么方法能够修改传入数组的元素？
- 为什么本练习返回 double，而不是在计算方法里直接输出？
